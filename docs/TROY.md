# 트로이 — 잘려 나간 차를 되살리다

한국 초기판(`8.apk`, 2013-01, v1.2.3)에는 `Troy` 라는 이름의 자산이 남아
있습니다. 그림을 뽑아 보면 **바퀴 달린 트로이 목마**입니다.

```
car/troy/troy            메시 + 본 + 애니메이션 (정점 1143 · 삼각형 1157)
car/troy/materials/troy  재질
car/troy/troy_lock       잠긴 차를 그릴 때 쓰는 그림
car/troy/player_troy_?   ← 없다
```

다른 차는 등급마다 `player_<이름>_<등급>` 프리팹이 있는데 트로이만
없습니다. 한국 마지막 정식판(7.7.0)에도, 중국판에도, 카카오판에도
흔적이 없습니다. **만들다 만 채로 잘린 차**입니다.

그래서 이 일은 자산을 옮겨 오는 일이 아니라 **없는 조각을 우리가 만들어
주는 일**이 됩니다.

```
python tools/addtroy.py --scan     무엇이 있고 무엇을 만들지 본다
python tools/addtroy.py            넣는다 (자산 · 번들 · 차 표 · 이름표)
python tools/troyicon.py           자동차 샵 아이콘을 만들어 넣는다
python tools/addtroy.py --remove   도로 뺀다
```

런처에는 붙이지 않았습니다. 헬리·태극호와 같이 **코드로만** 넣습니다.

## 1. 판본이 달라서 손봐야 했던 것

초기판은 **유니티 3.5.6f4**, 지금 빌드는 **4.1.5f1** 입니다. 직렬화 배치가
달라 파일을 그대로 옮길 수 없습니다. 값만 읽어 4.1 쪽 그릇에 옮깁니다.

| 무엇 | 초기판 (3.5) | 지금 빌드 (4.1) |
|---|---|---|
| 인덱스 | 삼각형 **띠** (`isTriStrip`) | 삼각형 목록 (`topology 0`) |
| 정점 | 한 줄기 stride 20 (좌표+UV 섞임) | 두 줄기 (좌표 12 · UV 8, 16바이트 경계) |
| 스트림 필드 | `align` | `dividerOp` · `frequency` |

띠를 풀어 목록으로 바꾸면 삼각형이 **1157개**가 나오는데, 이는 원본이
`triangleCount` 에 적어 둔 수와 정확히 같습니다. 도구는 이 값이 안 맞으면
멈춥니다.

뼈 가중치(몸통 756 · 바퀴 352 · 그림자 35)와 bindpose 는 값을 그대로
옮기되 **번호는 다시 매깁니다**(아래 8절). 트로이가 작게 나오지 않는 것은
bindpose 안에 0.189배가 이미 들어 있기 때문입니다.

실기 좌표로 재 보면 이렇습니다.

```
          너비    높이    길이
트로이     0.86   0.99    1.54
피닉스C    0.98   0.58    1.59
```

목마답게 **좁고 키가 큽니다.** 바닥에 닿는 높이도 피닉스와 같아(0.012 대
0.013) 길에 파묻히거나 뜨지 않습니다.

## 2. 프리팹은 등급마다 하나씩

번들에서 자산을 찾는 길은 **오브젝트 이름**입니다. 요청한 경로의 마지막
조각을 소문자로 만들어 이름표에서 찾습니다(`tunnelfix` 의 `__ChaFromBundle`).
이름 하나에 오브젝트 하나뿐이므로 **등급마다 프리팹이 따로 있어야**
합니다. 게임 코드에 박힌 서식이 이렇습니다.

```
Car/{0}/Player_{0}_{1}        차 프리팹      {1} = 등급
Car/{0}/Materials/{1}         재질
Car/{0}/Materials/{1}_{2}     재질 (등급별)
Car/{0}/{0}_Effect            효과
```

그래서 `Player_Troy_C · _B · _A · _S · _R` 과 `_Low` 까지 **열 벌**,
재질은 `Troy` · `Troy_C…R` · 각각의 `_Low` 까지 **열두 개**를 만듭니다.
프리팹 한 벌은 3KB 남짓이라 싼 값입니다.

이름이 겹치면 안 되는 자리가 두 군데 있습니다.

- **빌려 온 프리팹 안의 `Phoenix_C`** — 그대로 두면 진짜 피닉스를 가립니다.
  `Troy_Body` 로 바꿉니다. 다만 **뼈 이름(`Bone_body` 등)은 그대로 둡니다** —
  스크립트가 그 이름으로 찾습니다.
- **메시·텍스처의 이름** — `troy` 라는 열쇠는 **재질**이 써야 합니다
  (게임이 `Car/Troy/Materials/Troy` 로 다시 찾아 재질을 덮어씁니다).
  그래서 메시는 `Troy_Mesh`, 텍스처는 `Troy_Tex` 로 비켜 줍니다.

## 3. 프리팹 안의 값을 **다시 채운다**

빌려 온 프리팹을 그대로 두면 트로이가 피닉스 행세를 합니다. 타입트리가
없는 `MonoBehaviour` 라 그냥 지나치기 쉬운데, 실제로 이런 값이 박혀
있습니다. `sharedassets0.assets` 의 `MonoScript` 를 읽어 갈랐습니다.

| 스크립트 | 들고 있는 것 | 그대로 두면 |
|---|---|---|
| `CarDataLinker` | **CarIndex 를 글로** (`"27"`) | 트로이가 피닉스의 차 표를 물어 온다 |
| `BaseData` | 차 이름 · 무게 · 최고속 | 목마가 650kg 에 307km/h |
| `PlayerCarData` | 연비 · 가속 · 다음단 | 피닉스 성능 그대로 |
| `ChangeTextureMaterial` | 재질 두 개(본 재질 · 잠금) | `Start()` 에서 피닉스 재질로 덮어씀 |
| `JumpLanding` | 착지 소리 | — |

`eCarClassType` 은 차 프리팹 60여 개를 전수로 읽어 확인했습니다 —
`C=3 · B=2 · A=1 · S=0 · R=0`. S 와 R 이 둘 다 0 인 것은 원판이 그렇게
굽혀 있어서입니다.

## 4. 등급 사다리

트로이 자체의 수치는 어디에도 남아 있지 않습니다. 그래서 **이 게임 자신의
증가폭**을 그대로 따릅니다(AVEO 와 피닉스에서 확인했습니다).

```
최고속 +28 (R 은 +36) · 가속 +7 (+9) · 다음단 +7 (+9)
가속2  +0.7 (+0.9)    · 연비 +1.4 (+1.8)
```

시작값은 목마답게 **무겁고 조금 느리되 연비가 좋은** 쪽으로 잡았습니다.

| 등급 | 최고속 | 무게 | 가속 | 연비 |
|---|---|---|---|---|
| C | 291 | 1500 | 51 | 12.0 |
| B | 319 | 1600 | 58 | 13.4 |
| A | 347 | 1700 | 65 | 14.8 |
| S | 375 | 1800 | 72 | 16.2 |
| R | 411 | 1800 | 81 | 18.0 |

자동차 샵에 **트로피 15**로 나옵니다(복원한 특수차들과 같은 값).
CarIndex 18 · 서버 carNo 19.

## 5. 번들은 **다시 굽지 않는다**

`mkpack.py` 는 `packspec.txt` 를 처음부터 다시 합쳐 번들을 굽습니다.
그런데 그 목록이 가리키는 공여판 트리(맵 29개 · 보이스 220개)는 저장소에
없습니다 — 남의 APK 를 통째로 담아 둘 수 없어 걷어냈기 때문입니다.
지금은 `bundles/pack.unity3d` 자신이 그 자산들의 **유일한 사본**이고,
다시 구우려 들면 283개 중 249개가 사라집니다.

그래서 `tools/packadd.py` 를 새로 만들었습니다. 다시 굽지 않고 **이미 있는
`pack.dat` 위에 얹습니다.**

- 기존 오브젝트의 자리(offset·size)는 하나도 건드리지 않습니다.
- 새 오브젝트는 뒤에 붙이고 pathID 는 안 쓰는 번호부터 줍니다.
- 외부 파일 목록도 **뒤에만** 더합니다. 앞을 건드리면 기존 참조가 어긋납니다.
- 매니페스트(pathID 1)는 길어지므로 파일 맨 뒤에 다시 놓고 표만 고칩니다.
- 오브젝트 표가 237칸 늘어 머리가 길어지는데, 표의 `start` 는 **데이터
  구역 안에서 센 자리**라 값은 안 바뀝니다. 머리에 적는 시작 자리만
  새로 씁니다.

두 번 돌리면 두 번 붙으므로, `addtroy` 는 얹기 전에 늘 `backup/bundle` 에서
원래 번들을 되살립니다. 몇 번을 돌려도 결과가 같습니다.

```
오브젝트 2589 -> 2826 · 매니페스트 282 -> 306 · 7.32MB -> 7.54MB
```

## 6. 아이콘

`Atlas_SpecialCarIcon`(512×512, DXT5)에 `<차이름>_<등급>` 이름으로 미리
그려 둔 작은 그림이 들어 있습니다. 트로이 그림은 당연히 없습니다.
그래서 **모델을 그대로 렌더해서** 만듭니다(원판 아이콘들도 같은 모델을
찍어 만든 것입니다).

- 카메라는 거의 옆모습입니다. 원판은 3/4 앞옆인데, 목마를 그렇게 돌리면
  72×56 에서 갈색 덩어리가 됩니다. 여러 각도를 뽑아 보고 골랐습니다.
- 등급이 올라도 모양이 같으므로 **그림은 한 장만 넣고 스프라이트 다섯을
  같은 자리로** 가리킵니다.
- 판을 통째로 다시 압축하면 **이미 든 아이콘 42개까지** 한 번 더 손실
  압축을 먹습니다. DXT5 는 4×4 칸끼리 서로를 모르므로 **우리 그림이 덮는
  252칸만** 눌러 원본 바이트 사이에 끼워 넣습니다. 나머지 16132칸은
  바이트 하나 안 바뀝니다.
- 유니티 텍스처는 **아래에서 위로** 담기는데 아틀라스 좌표는 왼쪽 **위**가
  원점입니다. 줄 번호를 뒤집지 않으면 그림이 판 아래쪽, 이미 아이콘이
  있는 자리에 떨어집니다(한 번 그랬습니다).

가장자리를 깨끗하게 하는 데 두 번 헛발을 짚었습니다.

1. 그냥 줄였더니 실루엣 둘레에 **빨강·초록 점**이 박혔습니다. 란초스가
   바깥의 (0,0,0,0)을 색 계산에 끌어들여 울린 것입니다.
2. 알파를 곱해 두고 줄였더니 이번엔 **흰 테**가 생겼습니다. 중간에 uint8
   로 깎는 바람에 알파가 작은 자리에서 나눗셈이 튄 것입니다.

답은 **알파를 곱하고 · 넓이 평균(BOX)으로 · 실수로 줄이기** 였습니다.

## 7. 두 번째로 걸린 것 — 점프하면 목마만 길에 남았다

주행은 잘 되는데 **점프를 하면 목마 몸통은 길 위에 그대로 있고 바퀴와
아래 틀만 튀어올랐습니다.** 헬리처럼 상하부가 갈라지는 연출이 아니라
그냥 깨진 것이었습니다.

메시의 `m_Skin` 은 뼈를 **번호**로 가리키고, 그 번호는 렌더러
`m_Bones` 배열의 **자리**를 뜻합니다. 그런데 두 파일의 순서가 달랐습니다.

```
초기판 Troy 모델 : 0=Bone_body   1=Bone_wheel  2=Bone_shadow
피닉스 프리팹    : 0=Bone_shadow 1=Bone_body   2=Bone_wheel
```

번호를 그대로 둔 채 메시만 옮겼으니, 몸통 756정점이 **그림자 뼈**에,
바퀴 352정점이 **몸통 뼈**에 묶였습니다. 그림자 뼈는 길에 붙어 있고
몸통 뼈는 점프에 따라 올라가므로 정확히 그 증상이 납니다.

**서 있을 때는 티가 안 났습니다.** 뼈 사이 간격이 0.025 · 0.013 · 0.048 ·
0.074 로 다 합쳐야 0.1 남짓이라, 차고에서도 주행에서도 멀쩡해 보였습니다.
점프 애니메이션이 뼈마다 크게 다르게 움직이는 순간에야 갈라졌습니다.

고침: `rebone()` 이 두 파일에서 뼈 순서를 **이름으로** 읽어 번호를 옮겨
답니다(`m_Skin` 의 boneIndex 와 `m_BindPose` 배열 둘 다). 순서를 코드에
박아 두지 않으므로 다른 프리팹을 빌려 와도 그대로 맞습니다.

고친 뒤 실기: 목마와 바퀴가 함께 떠오르고 그림자만 길에 남습니다.

> **다음에 차를 옮길 때 꼭 볼 것** — 정지 화면은 이 오류를 안 보여 줍니다.
> **반드시 점프를 시켜 보세요.** 뼈가 크게 벌어지는 유일한 순간입니다.

## 8. 그 전에 걸린 것 — 맵이 한 걸음도 안 나갔다

차고에서도 자동차 샵에서도 트로이가 멀쩡히 섰고, 주행에 들어가 길 위에도
제대로 섰습니다. 그런데 **맵이 흐르지 않았습니다.** 거리·속도·점수가 전부
프리팹에 박힌 자리표시자(`00123456 7m`, `012 Km`)에 멈춰 있었습니다.

릴리스 빌드라 `Debug.Log` 가 logcat 에 안 나옵니다. 그래서 IL 을 읽었습니다.

```
EffectManager::Setting
   ldstr "Car/{0}/{0}_Effect"
   call  Generic_Title::__ChaResLoad(System.String)   ← 트로이는 없다 → null
   call  UnityEngine.Object::Instantiate(...)         ← Instantiate(null) 은 던진다
```

유니티의 `Instantiate(null)` 은 예외입니다. 그 예외가 `Player::Init` 의
준비 사슬을 끊습니다. 그 뒤에 있던 것들이 통째로 안 돌았습니다.

```
effectManager.Setting()                              ← 여기서 끊긴다
baseData.ResetLink()
mCollider = body.GetComponentInChildren<Collider>()  ← 충돌 상자도 못 얻는다
playerEffect.transform ... effectManager.defaultEffectObject.transform
```

**차의 충돌 상자가 효과 오브젝트 안에 들어 있다는 것**도 여기서 알았습니다.
피닉스 프리팹 자체에는 콜라이더가 없고, `Phoenix_Effect` 안의 `Collider`
게임오브젝트를 `Setting()` 이 차의 루트 본 밑으로 붙여 줍니다.

고침: `Phoenix_Effect`(미등 둘 · 콜라이더 하나, 오브젝트 13개)를 통째로
베껴 `Troy_Effect` 로 넣고 `car/troy/troy_effect` 이름을 답니다.

고친 뒤 실기: 거리 651m → 2794m(6초), 220km/h, 골드 5 → 35, 미등도 켜집니다.

**얻은 교훈** — 차 하나를 되살리려면 프리팹만으로는 모자랍니다. 게임이
차 이름으로 **따로 찾아 오는 것**이 무엇인지 IL 에서 전부 확인해야 합니다.
차마다 필요한 것은 이 넷입니다.

```
Car/{0}/Player_{0}_{1}    프리팹 (등급마다)
Car/{0}/Materials/{1}     재질
Car/{0}/{0}_Effect        효과 + 충돌 상자   ← 빠뜨리면 주행이 멈춘다
Car/{0}/{0}_Robot_Effect  로봇차만 (IsRobot)
```

`CarDataLinker::Update` 가 부르는 `Car/{0}/{0}@{1}`(애니메이션 클립)은
`linkNow` 가 꺼져 있으면 안 탑니다. 빌려 온 프리팹이 꺼진 채라 그대로 둡니다.

## 9. 되돌리기

```
python tools/addtroy.py --remove    차 · 번들 · 표 · 이름표
python tools/troyicon.py --restore  아틀라스 (backup/atlas)
```

CarDataBase 는 넣을 때 공백 자리에 같은 길이로 밀어 넣었으니 뺄 때도
같은 길이의 공백으로 되돌려 **파일 길이를 지킵니다.**
