# chatool — 다함께 차차차 통합 도구

세이브 런처 · 자산 뽑기/칠하기/들여오기 · APK 내보내기를 한 프로그램에 담았다.

## 머리말 — 기기 · 밝기 · 말

머리말 오른쪽에 **밝기**(시스템 따라 · 밝게 · 어둡게)와 **언어** 고르개가
있다. 고른 것은 `.uiconf.json` 에 남아 다음에 켤 때 그대로 온다.

### 기기

| 상황 | 머리말 |
|---|---|
| 붙어 있음 | 어느 기기인지 보여 준다 |
| 없음 | 왼쪽에 **다시 확인 단추**가 나온다 (꽂고 나서 누른다) |
| 둘 이상 | **어느 기기에 넣을지** 고르는 칸이 나온다 |

둘 이상일 때 고르는 것은 편의가 아니다. adb 는 기기가 둘이면 그냥
실패한다(`more than one device`). 그래서 고른 일련번호를 갈무리해 두고
**모든 adb 명령에 `-s` 를 붙인다**(`chatool.adb_cmd`). 넣기 · 가져오기 ·
지우기 · 앱 찾기 · 설치까지 전부 이 길로 간다. 골라 둔 기기가 빠지면
알아서 무시한다.

### 밝기

색은 **눈금(CSS 변수) 27개**로만 쓴다. 어두운 쪽이 기본이고 밝은 쪽은
값만 갈아 끼운다. `data-theme` 이 없으면 시스템을 따른다.

```
:root                                    어두운 쪽 (기본)
:root[data-theme=light]                  밝게 골랐을 때
@media(prefers-color-scheme:light)
  :root:not([data-theme=dark])           시스템이 밝을 때
```

**색을 굳혀 쓰면 안 된다.** 밝은 쪽 정의에서 그 색이 빠지므로 어두운 값이
그대로 남는다. 입력칸 바탕을 굳혀 두었더니 밝은 판에서 글자가 통째로
파묻혔다 — 실제로 겪었다. 3D 캔버스도 `--code` 를 읽어 밝기를 따라간다.

### 설정 파일은 통째로 갈아 끼운다

`.uiconf.json` 은 임시 파일에 쓴 뒤 `os.replace` 로 바꾼다. 예전에는 그
자리에서 고쳐 썼는데, 런처와 CLI 가 같이 돌면 다른 쪽이 **반만 쓰인
파일**을 읽고 기본값으로 되돌아갔다. 그다음 저장이 그 기본값을 굳혀
**고른 언어가 소리 없이 한국어로 돌아갔다.** 읽기가 어긋나면 마지막으로
제대로 읽은 값을 쓴다.

번역은 `lang/` 안의 json 하나가 한 언어다.

```
lang/en.json    {"_name": "English", "세이브": "Saves", …}
lang/kr.json    {"_name": "한국어",  …}
```

**열쇠는 한국어 원문 그대로**다. 그래서

- 새 언어를 붙일 때는 `en.json` 을 복사해 값만 바꾸면 된다.
- 번역이 빠진 자리는 한국어로 나오므로 **어디가 덜 됐는지 바로 보인다**.
- 코드에서 `T('세이브')` · `_msg('저장했습니다: %s')` 라고 읽혀 무슨 말인지
  열쇠만 봐도 안다.

같은 한국어가 다른 언어에서 갈리는 자리는 열쇠 뒤에 **뜻 가름표**를
붙인다. 한국어로 볼 때는 떼어 내므로 화면은 그대로다.

```
T('기록|주행')  ->  Records   (세이브의 주행 기록)
T('기록')       ->  History   (런처가 한 일)
```

지금 갈라 둔 것은 넷이다 — `기록` · `기본` · `이름` · `내용`.

자리 채우기는 중괄호(화면)와 `%s`(서버) 둘 다 쓴다 —
`T('세이브 {n}개', {n:3})` · `_msg('저장했습니다: %s') % name`.

옮김이는 넷이다. 하는 일은 같고 부르는 자리만 다르다.

| | 어디서 |
|---|---|
| `T()` | 화면(JS) |
| `_msg()` | `chatool.py` 의 런처 백엔드 |
| `_L()` | `chatool_assets.py` (자산 · 진행 로그) |
| `t=` 인자 | `chasaves` · `chahost` · `chabuild` — **안 주면 한국어 그대로**다 |

`FORMATS` · `CATS` 처럼 **표에 박아 둔 말은 원문으로 둔다.** 그 자리에서
옮기면 모듈이 실릴 때 굳어 언어를 바꿔도 안 따라온다 — 쓰는 자리에서
옮긴다.
**게임의 것은 옮기지 않는다.** 도 강현 · 갸루상 · 고급휘발유 같은 이름은
어느 말로 보든 그대로다.

화면에 말을 새로 넣었으면 열쇠를 맞춰 넣는다. **이미 있는 번역은 안
건드린다.**

```
python tools/langkeys.py                        모자란 것만 본다
python tools/langkeys.py --write                lang/*.json 을 맞춰 쓴다
python tools/langkeys.py --new ja --name 日本語  새 언어 뼈대를 만든다
```

```
python tools/chatool.py <명령>          파이선이 있는 PC
dist\chatool.exe <명령>           파이선이 없는 PC (pack-exe 로 만든다)
```

명령 없이 실행하면 런처가 열린다.

## 얼굴 둘, 속은 하나

| 명령 | 무엇 |
|---|---|
| `chatool` | **앱 창**으로 열립니다 (기본) |
| `chatool app` | 같은 것 — 명시적으로 창 |
| `chatool web` | 브라우저 탭으로 엽니다 |

둘은 **같은 백엔드(`_api`)** 를 씁니다. 기능도 동작도 완전히 같고,
창이냐 탭이냐만 다릅니다. 창은 pywebview 로 띄우고, 윈도우에서는
Edge WebView2 를 빌려 씁니다(윈도우 10/11 에 기본으로 깔려 있습니다).
그것이 없는 환경에서만 브라우저로 물러섭니다.

화면은 탭 여섯이다.

```
플레이어 · 자동차 · 드라이버 · 아이템·스킬 · 초대·공지 · 자산·모델
└──────────── 세이브 편집 ────────────┘   └── 자산·빌드 ──┘
```

## 세이브 관리 (왼쪽 기둥)

- `saves/` 아래에 여러 개 둘 수 있고, **한 번에 하나만 고른다.**
- 고른 것이 `chastate.json` 으로 복사돼 서버가 읽는다.
- 새로 만들기 · 복제 · 이름 바꾸기 · 삭제 (마지막 하나는 못 지운다)
- **ADB 연결 시**: 기기에 넣기 / 기기에서 가져오기
  (`/storage/emulated/0/Android/data/com.cjenm.chachacha.revive/files/chasave.json`)

로컬 전용 APK 도 **같은 스키마**를 쓴다. 그래서 세이브를 서버판과
로컬판 사이에서 그대로 옮겨 다닐 수 있다.

편집할 수 있는 것 — 별명 · 골드 · 트로피 · 타이어 · 타고 있는 차 · 드라이버 ·
주행 기록 · 보유 차량 30대 · 차량 등급 · 보유 드라이버 12명 · 아이템 7종 ·

## 자산·모델 탭

### 차와 자산 고르기
등급마다 모델이 따로다 (`Meteor_A` · `Meteor_S` · `Meteor_R`,
그리고 각각의 `_LOW`). 그래서 드롭다운이 둘이다 — 차를 고르면
그 차의 모델 목록이 채워지고, 아래에 **번들 안의 모든 메시 202개**가 붙는다.

이름이 딴판인 차가 있어서 전체 목록이 필요하다:

| 차 | 실제 자산 이름 |
|---|---|
| PRIUS | `CAR_Prius` |
| Challenger | `Dodge Challenger` |
| Evoque | `RANGEROVER` |
| GTR | `nissan_GTR` |
| McLaren | `mp4-12c` |
| Boxster | `SEED` (게임 이름이 '시드') |

메시와 텍스처의 이름이 아예 다른 것도 있다 — 프리우스는 메시가
`CAR_Prius`, 텍스처가 `PRIUS` 다. 그래서 둘을 **따로** 찾고, 그래도 못
찾으면 **머티리얼을 따라간다**(`m_Materials[0] -> _MainTex`). 덕분에
`86_A` · `BEETLE` 처럼 차 목록에 없는 메시도 텍스처가 붙는다.

### 3D 미리보기
WebGL 로 그린다. 라이브러리를 쓰지 않아 브라우저만 있으면 된다.
끌면 돌고, 휠로 확대한다.

- **보통** — 텍스처를 입혀 실제로 보이는 대로
- **감기 검사** — 뒷면 감추기를 끄고 뒤집힌 면을 **빨갛게** 칠한다
- **뼈대** — 선으로만

**감기 검사가 이 도구에서 제일 값진 자리다.** 이 게임의 차는 스키닝
메시라 차고(쉬는 자세)에서는 뒤집힌 면이 드러나지 않는다. 기기에 넣고
주행 화면까지 가야 새까만 게 보인다. 여기서 미리 본다.

밑에 자동 진단도 뜨는데, 보는 값이 둘이다.

- **모서리 짝** — 면끼리 감기가 어긋나지 않았는가
- **부호 있는 부피** — 통째로 뒤집혔는가

무게중심으로 안팎을 세는 흔한 방법은 **이 게임에는 못 쓴다.**
원본 차들도 전부 50% 가 나온다 — 차 메시가 속이 빈 얇은 껍데기라
겉면과 속면이 반반이기 때문이다. (실측해 보고 알았다.)

### 뽑기 · 다시 칠하기 · 새 차 추가
- `뽑기` — 텍스처 PNG · 메시 OBJ · **UV 안내선 PNG** 를 `extract/<이름>/` 에
- `다시 칠하기` — PNG 를 끌어다 놓고 누르면 DXT1 로 눌러 제자리에 넣는다
  (크기 자동 맞춤 · 길이 보존이라 다른 자산은 건드리지 않는다)
- `모델 들여오기` — OBJ + 텍스처 PNG 를 끌어다 놓고 이름·등급·값을 정하면
  **차 한 대를 새로 만들어** 자동차 상점에 올립니다. 기존 차를 덮어쓰지
  않습니다 (`chatool newcar`)

원본은 `backup/` 에 남는다. **작업 트리 밖**이라 APK 에 딸려 들어가지 않는다.

### 오른쪽 칸은 키가 고정이다
텍스처와 UV 안내선을 **나란히** 두면 뽑을 때마다 오른쪽 칸이 길어져
아래 카드가 통째로 밀렸다. 그래서

- 둘을 한 자리에 겹치고 위에 `텍스처 | UV 안내선` 단추를 뒀다
- 그림 자리는 늘 206px, `이 차` 표는 뽑기 전에도 같은 줄 수로 `—` 를 채운다

덕분에 뽑기 전후로 `자산 내보내기` 단추의 세로 위치가 **1px 도 안 움직인다**
(실측). 그림을 누르면 화면 가득 키워 본다 — 256×256 짜리 텍스처도 크게.

### 동작 보기 — 뼈가 잡는 자세까지
미리보기 밑에 `동작` 줄이 있다. 클립을 고르면 **그 자리에서 재생된다.**
막대를 끌어 프레임을 하나씩 볼 수도 있다.

이 게임의 차는 스키닝 메시라 차고(쉬는 자세)만 봐서는 반쪽이다. 실제로는
뼈가 자세를 잡는다. 프리우스만 해도 `damage` · `explosion` · `jump` ·
`race` · `rotate` 다섯 가지가 붙어 있다.

셈은 이렇게 나눠 놓았다.

- **서버가 굽는다** — 프레임마다 뼈별 스키닝 행렬(월드 × 역바인드)을
  미리 계산한다. 뼈가 3~28개뿐이라 클립 하나가 3~22KB 다.
- **화면이 섞는다** — 정점마다 그 행렬을 가중치로 섞는다(CPU). 정점이
  1000개 안쪽이라 넉넉하다. 법선도 프레임마다 다시 계산한다 — 안 그러면
  차가 움직여도 빛이 따라오지 않아 종이처럼 보인다.

화면 잡는 자리도 동작에 맞춘다. `jump` 처럼 크게 솟는 동작은 정지 자세
기준으로 잡으면 재생 내내 차가 화면 밖에 있다.

처음 한 번은 **뼈대 색인**을 만들어야 한다(`SkinnedMeshRenderer` 가 있는
파일을 훑는다, 몇 분). 없으면 그 자리에 단추가 뜬다.

색인은 작업 트리만이 아니라 **번들에 담기는 원본**(`packspec.txt` 가
가리키는 파일들)도 함께 본다. 헬리처럼 이식해 넣은 차는 프리팹과 클립이
`gogo142/` 쪽에 있어서, 그걸 빼면 변신 동작(`car2robot` · `robot2car`)이
안 잡힌다. 표에는 어느 뿌리에서 왔는지도 적어 둔다.

세 가지를 골라 잡아야 제대로 나온다.

- **어느 프리팹인가** — 메시 파일 자신에도 렌더러가 딸려 있지만(FBX 가
  통째로 들어온다) 거기엔 클립이 없다. 후보가 여럿이면 `Animation` 이
  붙은 쪽을 고른다.
- **어느 Animation 인가** — 헬리는 차와 로봇이 **한 파일**에 있다. 첫
  번째를 집으면 뼈가 딴 가지로 간다. 렌더러의 조상 중 가장 가까운
  `Animation` 을 쓴다(클립 경로가 바로 그 자리 기준이다).
- **가중치가 눌려 있는가** — `_LOW` 판들은 `m_Skin` 이 비어 있고
  `m_CompressedMesh` 안에 비트열로 들어 있다. 31 을 꽉 찬 값으로 보는
  고정소수점이라, 합이 31 이 될 때까지 읽고 셋째까지 안 차면 넷째를
  `31 - 합` 으로 채운다.

### 자산 내보내기
**내려받기가 아니라 PC 폴더에 직접 쓴다.** 창 런처(webview)는
`<a download>` 가 먹지 않아 예전 'OBJ 내려받기' 링크가 죽어 있었다.
이제 서버가 `export/<이름>/` 에 쓰고 끝나면 탐색기로 그 폴더를 연다.

범위는 셋 — `지금 보고 있는 것 하나` · `차고에 있는 차 전부(30대)` ·
`목록에서 골라서`(202개 메시를 이름으로 걸러 고른다).

| 형식 | 무엇 |
|---|---|
| `.obj` + `.mtl` | 블렌더·3ds맥스용. MTL 이 PNG 를 물고 온다 |
| `.glb` | glTF 2.0 한 덩어리. **텍스처까지 안에** 넣어 윈도우 3D 뷰어가 바로 연다 |
| `.stl` | 3D 프린터·조형용 (색·UV 는 못 담는다) |
| `.png` | 텍스처 원본 |
| `_uv.png` | UV 안내선 |
| `.json` | 어느 자산 파일 몇 번인지 · 정점/삼각형/크기 |
| `_anim.glb` | **뼈대와 동작까지** 담은 glTF. 블렌더에서 그대로 재생된다 |
| `_anim.json` | 프레임별 뼈 행렬을 그대로 적은 것 |

동작 glTF 가 맞아떨어지는 이유가 있다. 유니티의 역바인드에는 **렌더러의
월드 행렬이 이미 들어 있고**, glTF 도 스킨 메시 마디의 자체 변환을
무시하도록 규정돼 있다. 그래서 유니티가 하던 셈과 모양이 같아 뼈만 옮겨
심으면 된다. 축은 맨 위에 마디를 하나 씌워 X축 -90° 로 돌린다.

내보낸 glb 를 다시 풀어 굽기 결과와 맞대 보았다 — **최대 차이 5e-6**
(반올림 수준). 셈이 어긋나지 않았다는 뜻이다.

좌표계가 형식마다 다르다. **OBJ 와 STL 은 게임 좌표 그대로**
(x 좌우 · y 앞뒤 · z 높이, Z-up) 두고, **glTF 는 규격이 Y-up 으로
못박혀 있어 눕혀서** 내보낸다. 축 회전이라 감기는 그대로다.
법선은 게임 메시에 없어서 면 법선을 정점마다 평균 내 만든다.

`전부` 로 뽑으면 차 이름(`Evoque`)을 자산 이름(`RANGEROVER`)으로
바꿔 주는 길을 탄다. 안 그러면 별명 붙은 다섯 대가 조용히 빠진다.

### APK 만들기
같은 탭 맨 아래. 서버용/로컬 전용을 고르고 `APK 만들기`.

## 명령줄로도 똑같이

```
chatool cars                          차 30대 목록 (번호·등급)
chatool extract Meteor_A              텍스처 PNG · 메시 OBJ · UV 안내선
chatool repaint Meteor_A new.png      텍스처만 갈아 끼운다
chatool import  my.obj --like Meteor_A            그 차의 메시만 갈아 끼웁니다
chatool newcar  Taegeukho --obj a.obj --png b.png --label 태극호 --class S
                                                 새 차로 추가합니다
chatool index                         자산 색인 다시 만들기 (몇 분)
chatool build [--mode server|local] [--install]
chatool pack-exe                      dist\chatool.exe 를 만든다
```

## 두 가지 APK

```
chatool build                     서버용 chacn_ko.apk
                                  PC 의 chacnserver.py 와 이야기한다
chatool build --mode local        로컬 전용 chacn_local.apk
                                  서버 없이 폰 안에서 다 끝낸다
```

로컬 전용은 세이브를 폰 안에 두고, 복원한 맵 번들(5.3 MB)을 APK 안에
넣는다. 자세한 것은 `LOCALAPK.md`.

패키지 이름이 같아 **둘은 서로 덮어쓴다.** 한 번에 하나만 깔린다.

## 모델을 새로 만들 때

**Blender**(무료)로 만들고 OBJ 로 내보낸 뒤 들여오면 된다.

- 좌표계: x 좌우 · y 앞뒤(길이) · z 높이.
  Blender 에서 **Z-up / Forward -Y** 로 내보내면 맞는다.
- `--like <자산>` 으로 준 모델의 크기·자리에 자동으로 맞춘다.
- 정점은 (위치, UV) 가 같으면 자동으로 합친다.
- 넣기 전에 **감기 검사**로 보고, 넣은 뒤에는 **주행 화면**을 확인하라.
  까맣게 나오면 앞면 방향을 '통째로 뒤집기'로 다시 넣는다.

### 다시 칠하기가 가장 값싸고 효과가 크다
원본 차가 잘생겨 보이는 이유의 대부분은 폴리곤이 아니라 **텍스처 그림**이다.
검증된 메시와 UV 를 그대로 두고 그림만 바꾸면 첫판부터 게임 원본 수준으로 보인다.

추천 도구: **Aseprite**(픽셀) · **Krita**·**GIMP**·**Photopea**(무료) · Photoshop

## 파이선 없는 PC 용

```
python tools/chatool.py pack-exe     dist\chatool.exe 를 만든다
```
exe 는 `dist\` 안에 떨어지는데, 거기서 그대로 실행해도 한 칸 위의
작업 트리를 찾아 쓴다. exe 하나만 들고 가면 런처와 자산 도구가 그대로 돈다.
(굽기 전에 **돌고 있는 chatool.exe 를 먼저 내려라.** 파일을 잡고 있으면
PyInstaller 가 조용히 실패하고 옛 exe 가 그대로 남는다.)
다만 APK 재조립은 `jarsigner`·`adb` 가, 로컬 전용 빌드는 추가로
`csc`(v3.5)가 그 PC 에 있어야 한다.

## 알아 둘 것

- 자산 도구는 UnityPy 를 쓴다. 런처는 요청마다 스레드를 띄우므로
  `chatool_assets` 모듈 본문에서 **한 번만** 들여온다. 함수 안에서
  들여오면 두 스레드가 순환 임포트를 함께 밟아 깨진다.
- 오래 걸리는 일(색인·빌드)은 작업(job)으로 돌고 화면이 `/api/job` 으로
  들여다본다. 진행 칸에 그대로 찍힌다.
- 로컬 전용 빌드는 `logcat` 에 `[ChaLocal]` 로 오간 것을 다 남긴다.
