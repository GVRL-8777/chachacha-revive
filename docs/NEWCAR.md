# 새 차 추가 — 덮어쓰지 않고 한 대를 늘립니다

`chatool import` 는 기존 차의 메시만 갈아 끼우는 도구라 차 대수가 늘지
않습니다. 이쪽은 차 한 대를 통째로 새로 만들어 넣습니다.

```
chatool newcar Taegeukho --obj my.obj --png my.png --label 태극호 --class S
```

런처에서는 **자산·모델 탭 → 모델 들여오기** 카드에서 같은 일을 합니다.

## 하는 일 다섯

| | 무엇 | 어디에 |
|---|---|---|
| 1 | 메시(압축) · 텍스처(DXT1) · 재질 · 프리팹 한 벌 | `<이름>.assets` |
| 2 | CarDataBase 항목 한 줄 | `x77/…/ade64ecd…` |
| 3 | 이름표 `CarName_<이름>` | `x77/…/50295c6b…` |
| 4 | 번들 목록 한 줄 → 번들 다시 굽기 | `packspec.txt` · `bundles/pack.unity3d` |
| 5 | 서버·세이브가 읽는 표 | `newcars.json` |

프리팹은 기존 S급 차(람보르기니)에서 **통째로 베낍니다.** 본·애니메이션·
스크립트가 그대로 붙어 있어야 차고에서도 주행에서도 제대로 섭니다.
`ChangeTextureMaterial` 이 `Start()` 에서 재질을 덮어쓰므로 그 배열의
참조까지 새 재질로 돌려놓습니다(그걸 빼먹으면 차가 단색으로 나옵니다).

## CarDataBase 는 **빈 자리에** 씁니다

항목을 덧붙이면 텍스트 자산이 길어져 파일을 통째로 다시 써야 합니다.
`trimcars.py` 가 비워 둔 공백 자리에 같은 길이로 밀어 넣어 **파일 길이를
지킵니다.** 빈 자리가 모자라면 그렇게 말하고 멈춥니다.

CarIndex 는 안 쓰는 번호 중 가장 작은 것을 고릅니다.
서버 carNo 는 언제나 CarIndex + 1 입니다.

## 표는 한 곳에서만 고칩니다

`newcars.json` 한 파일을 `chastate.py`(세이브·런처)와
`carfix.py`(서버)가 읽어 각자의 표에 얹습니다. 새 차는 상점 매물로
들어가므로 게임 안에서 사서 타면 됩니다.

로컬 전용 APK 는 `mkskel.py` 가 서버 표를 떠서 `ChaLocalData.cs` 로
굽습니다. 그래서 순서가 있습니다.

```
newcar → carfix.py (서버 표) → mkskel.py → chatool build --mode local
```

`chatool build` 는 이 중 마지막만 합니다. 새 차를 넣은 뒤에는
`relaunch2.sh`(서버판) 또는 위 순서(로컬판)를 한 번 돌리세요.

## 실기로 확인한 것

람보르기니 메시·텍스처를 그대로 뽑아 `시험차`(S급, carNo 19)로 넣었더니
자동차 샵에 **S class 시험차**로 뜨고, 성능 막대와 가격(트로피 150)까지
정상이었습니다. 예외 0.

## 뺄 때

```
chatool newcar Testcar --remove
```

넣을 때 공백 자리에 밀어 넣었으니 뺄 때도 **같은 길이의 공백**으로
되돌려 파일 길이를 지킵니다. 이름표·packspec·번들·`newcars.json`·
`<이름>.assets` 까지 함께 정리합니다. 그다음 서버 표를 다시 만들고
(`carfix.py` → `mkskel.py`) APK 를 다시 만드세요.

시험용으로 넣었던 `시험차`(carNo 19)는 이 경로로 깨끗이 뺐습니다
— CarDataBase 30대, 이름표·번들·APK 어디에도 남지 않았습니다.

## 주의

- 넣기 전에 런처의 **감기 검사**로 뒤집힌 면이 없는지 보세요.
  차고에서 멀쩡해 보여도 주행에서 새까맣게 나오는 일이 있습니다.
- 텍스처는 원본 차와 같은 크기(256×256)로 맞춰집니다.
- 아이콘(자동차 목록의 작은 그림)은 아직 원본 차 것을 씁니다.
  따로 넣으려면 `Atlas_CarIcon` 에 스프라이트를 더해야 합니다.
